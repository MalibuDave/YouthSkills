New topic: Bishopric page and tool set (topic 12).

Context docs: topics/11-account-creation-requirements.md (primary),
04-bishop-ward-onboarding.md, 08-bishopric-account-maintenance.md,
07-reporting.md, 06-key-completion.md.

Goal: define what a bishopric member sees and can do in V1, so it can
be added to the wireframe. Output should be a topic doc in the same
style as topic 11: decisions table, screens, states, permissions,
open questions, out of scope.

Ground rules:
- Every view or tool must lead to a decision or action (topic 07).
  If nothing leads to an action, it's out of V1.
- Bucket everything: must-have for launch / can follow / future-scale.
- Bishopric is a role on a ward (User → RoleAssignment → Ward),
  not an is_bishop flag.

Already decided (topic 11): approval queue tabs (Pending / See
Bishopric / Rejected / Active), the four actions, optional reject
note, decision history with who/what/when.

Start with these open questions:
1. Roles: one "Bishopric" role in V1, or separate bishop / counselor / clerk?
2. Notifications: is the bishopric emailed on new requests? Digest or per request?
3. Ward changes: an active youth switching wards; "remove from ward"
   vs "delete account"; can a bishopric delete accounts at all?
4. Key completion: what the bishopric sees and does when a youth
   earns a Key (notification, certificate, roster view).
5. Profile: what's on the bishop's own profile page vs the ward tools.
