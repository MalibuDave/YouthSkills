# Topic 01 — Product Vision & Content Model
Scope: what the product is, the Key/Lesson structure, visual identity of Keys, and how Bishop Porter's existing material gets brought in.

## Product definition
- Web app (wireframe → beta) that teaches LDS youth practical life skills that benefit them as they become adults.
- Skills are called **Keys**. Each Key has its own icon and associated lessons. The site provides learning material and tracks progress.
- Should feel engaging and youth-appropriate, not like a conventional school LMS. Progress should feel like unlocking capabilities for adulthood.
- Long-term vision (Bishop Porter): form a 501(c)(3), print and sell the material cheaply as books, other charitable work.

## Content hierarchy (agreed)
Program → Group → Key → Lesson → Section/Activity → Progress
- A **Key** is a collectible, visually identifiable achievement, not just a nav category.
- Key states on a dashboard: not started / in progress / completed (earned).
- Example Group: **Outdoors** — Bird Watching, Mountain Biking, Kayaking, River Rafting, Camping, Hiking, Fishing, Astronomy, Horseback Riding.

## Key visual system (from the reference poster)
- Circular badge emblem, gold border, illustrated subject, prominent skill name, outdoor/scouting heritage feel.
- Palette cues: dark forest green, gold, cream. The whole site need not look like the poster; the Keys carry much of the personality.
- Preserve the badge artwork rather than reducing Keys to generic UI icons.

## Lesson structure (from the Book of Mormon Key example)
- A Key opens into: introduction/purpose, expected benefits/outcomes, scripture study, contextual explanation, practical application, reflection, completion.
- A lesson can contain several smaller units. Example section: **1 Nephi 3:7 — Obedience to Commands** → Scripture/Key Quote, Background, Why It Matters, ✓ Mark section complete.
- Don't reproduce posters as giant images; render content as responsive components (phones especially).
- Key page shows progress, e.g. "5 of 8 lessons completed — 63%".

## Content-as-data principle
- Scripture refs, lesson text, requirements, images, and completion rules stored as structured content; the site renders it.
- Goal: an authorized person (e.g., Bishop Porter) can add a Key without anyone hand-building a page.

## Bishop's source material
- Hundreds to thousands of pages from years of iteration; likely includes obsolete ideas, duplicate/renamed Keys, conflicting structures.
- Plan: establish a source hierarchy before ingesting — **Current/Canonical → Active Draft → Historical/Deprecated** — and consolidate rather than upload hundreds of separate files.

## Open questions

- Age ranges / prerequisites per Key.
- How printed-book versions relate to digital content (offline completion credit?).
